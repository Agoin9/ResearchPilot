\## 1️⃣ 目标用户与痛点



\*\*用户\*\*：硕/博研究生——科研周期长（3个月\~3年）、每周可用时间少（5\~20小时）、有拖延倾向。



\*\*5 大痛点 → 解法\*\*：



| 痛点 | 解法 |

| --- | --- |

| 大目标不知道怎么拆解 | AI 自动拆成「里程碑 + 任务」 |

| 手工排期繁琐 | AI 按截止时间 + 每周可用时间自动排期 |

| 延期了后知后觉 | 本地规则引擎实时识别风险，红/黄标记 |

| 延期后不知道怎么办 | AI 重规划，一键采纳自动调整任务 |

| 没反馈没动力 | 进度记录 + 可视化图表 |



\*\*使用流程\*\*：新建项目（目标/截止时间/每周小时）→ AI 拆解预览 → 确认写入看板 → 日常更新进度 → 自动风险提醒 → AI 重规划 → 采纳/放弃（历史留档）。



\## 2️⃣ 架构与数据流



```

浏览器（React+TS+Vite+Tailwind+shadcn/ui+Recharts）

&#x20;       │ HTTP/JSON

&#x20;       ▼

FastAPI 后端：路由层 → 业务层（拆解/风险/重规划/统计）→ SQLAlchemy

&#x20;       │                    │

&#x20;       ▼                    ▼

SQLite 本地库          DeepSeek API（仅后端调用，Key 不暴露给浏览器）

```



\*\*关键设计\*\*：① 前端不直接调 DeepSeek；② 风险识别是纯本地规则，不消耗 AI token；③ AI 调用失败自动降级为手动模式，核心功能不依赖 AI。



\## 3️⃣ 数据库 4 张表



\- \*\*project\*\*：名称、科研目标、截止日期、每周可用小时、状态

\- \*\*task\*\*：所属项目、父任务（里程碑）、标题、状态（待做/进行/完成）、优先级、计划起止、预计耗时、进度%、排序

\- \*\*progress\_record\*\*：任务、更新后进度、本次投入小时、备注、时间（用于图表和历史时间线）

\- \*\*replan\_history\*\*：项目、触发原因（手动/风险）、风险快照 JSON、方案内容、结构化变更 JSON、状态（待处理/已采纳/已放弃）



\## 4️⃣ 前端页面（8 个）



1\. \*\*仪表盘\*\* `/`：项目概览、风险提醒区、完成趋势图、状态分布饼图、投入统计

2\. \*\*项目列表\*\* `/projects`

3\. \*\*新建项目向导\*\* `/projects/new`：表单 → AI 拆解预览（可增删改）→ 确认创建

4\. \*\*项目看板\*\* `/projects/:id`：三列（待开始/进行中/已完成）+ 风险横幅 + AI 重规划入口

5\. \*\*任务详情弹窗\*\*：更新进度（滑块+投入时间+备注）+ 进度历史时间线

6\. \*\*重规划方案弹窗\*\*：方案展示 + 变更预览 + 采纳/放弃

7\. \*\*重规划历史\*\*：历史方案列表

8\. \*\*项目统计页\*\* `/projects/:id/stats`：进度折线、里程碑完成情况、投入对比



\## 5️⃣ API 接口（共 18 个，前缀 /api）



\- \*\*项目类 6 个\*\*：增删改查 + 列表 + 统计数据

\- \*\*任务类 5 个\*\*：创建、更新、删除、新增进度记录、进度记录列表

\- \*\*AI 类 7 个\*\*：拆解（返回草稿）、确认拆解、重规划、历史列表、采纳、放弃 + 健康检查

\- \*\*风险不单独设接口\*\*：随项目列表/详情响应附带返回，零额外请求



\## 6️⃣ 开发顺序（8 个里程碑）



M1 工程骨架 → M2 后端数据层（4 表+CRUD）→ M3 前端基础（路由/布局/封装）→ M4 项目模块（向导+看板）→ M5 进度与图表 → M6 风险识别 → M7 AI 集成（拆解+重规划）→ M8 打磨验收。\*\*每个里程碑完成即可运行可演示\*\*，每阶段有独立验收标准（详见文档 §11）。



\*\*主要风险\*\*（详见文档 §12）：DeepSeek 输出格式不稳定（→强约束 Prompt+校验+重试+降级）、API 不可用（→核心功能与 AI 解耦）、小白环境配置难（→傻瓜式 README+启动脚本）。
